# Limits and release gates

- **No native Windows lab validation.** The development workstation's Windows PowerShell can parse scripts, but lacks the configured dedicated IIS/.NET10/Sysmon lab and elevation. No native attack, capture, GUID attribution or hardened host retest passed. Exact remaining gates are in the [Windows runbook](windows-runbook.md#required-evidence-before-a-validated-windows-release).
- **Fixtures are authored, not captured.** The two splits vary values/order within one behavioural model. Their outcomes establish implementation behaviour and expose selected blind spots, not field accuracy, real attack prevalence or external validity. A new held-out set is needed after tuning to its current outcomes.
- **Evidence has boundaries.** Missing policy context misses cross-tenant abuse. Uninstrumented execution can alert while remaining unattributed. Time/PID-only links are weak; conflicting candidates remain ambiguous. A file creation is not a read, and a connection is not a proven transfer. The native receiver must confirm content and sender/receiver hashes.
- **Rules are narrow.** Image-name predicates miss renamed tools and abuse inside a worker or trusted helper. Legitimate interpreter maintenance still produces a false alert. Root/destination policy is deployment-specific. No suppression based on a scenario label is used.
- **Collection is batch and bounded.** Manual exports plus report processing are not a live monitoring cadence. Reported replay time and retained bytes do not measure live detection delay, collection CPU, analyst productivity or operational savings. W3C rows cannot be reliably deduplicated across files without trustworthy identity.
- **Preview engineering scope.** This is a small loopback lab API with synthetic credentials, not a production portal or SIEM. No AD, persistence, web shell, security bypass or arbitrary-target scanning is implemented. Keys are stored under owned state and protected by filesystem permissions, not a production key vault.
- **Validation platform limits.** Local checks used Linux/WSL and native Windows PowerShell static tests. [Hosted CI passed](https://github.com/quocbao210/iis-purple-lab/actions/runs/35430608975) for Python replay on Windows/macOS/Linux, application checks on Linux and PowerShell static checks on Windows. Shared runners do not install the native lab, execute host payloads or collect native scenario telemetry.

A **validated Windows release** requires all portable gates plus observed native topology/permissions, original relevant Windows events, source provenance, case-level attribution review, same-request vulnerable/hardened outcomes, benign regressions, receipt hash verification, and containment/rollback/cleanup checks. Until then the release name stays portable preview.
