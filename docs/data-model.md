# Evidence schema and attribution contract

Each dataset has `manifest.json` with `origin`, `collected_at`, collection conditions, tool/configuration versions and `files`: relative path, source, format and SHA-256. Supported sources: `iis`, `application`, `sysmon`, `security`, `powershell`, `sink`. Formats: UTF-8 JSONL, W3C with actual `#Fields`, and structured event XML. Excluded sources are not opened.

Normalized records have content-derived `evidence_id`, `source`, UTC `timestamp`, separate `collected_at`, `host`, and `source_ref` (file, record number, original hash). Duplicates retain all source references. Windows records retain provider, channel, event ID/version/record identity and named fields. Sysmon payload time is the event timestamp; System.TimeCreated is also retained where present. Hexadecimal 4688 PIDs are decoded; absent command lines remain absent. PowerShell fragments retain individual evidence and completeness/conflict markers; incomplete fragments are not silently treated as a complete script.

Application fields include server-generated request ID, separately untrusted client ID, authenticated actor/tenant/role, resource tenant/ID, sharing list, policy decision, action and outcome. Launch records add request/job, host, parent PID/start, child PID, launch start/end, image and command line. No credentials or cookies belong in these records. The normalizer whitelists fields and redacts sensitive query keys; retained original evidence can still contain private data and must be handled accordingly.

Process records use host + ProcessGuid; ancestry uses ParentProcessGuid, not a numeric PID alone. Launch joins are bounded to the recorded start/end plus a two-second skew allowance, with intervals over 120 seconds rejected. Long-running job descendants can outlive a request and keep GUID ancestry; the launch itself remains bounded. Concurrent launches without a unique owner are ambiguous. Recycling requires the observed parent start to agree. Time-only, missing and unattributed paths remain visible.

Attribution reporting rubric: a high link satisfies every identity/time/success condition above; ambiguous means multiple viable owners/processes; low means some launch evidence without sufficient unique identity; unattributed means an independently observed process has no instrumented owner. Per-case high-link counts require the known evaluation request ID and are counts, not an independently measured correctness percentage. Background workers also remain unattributed and are included in global link counts. Automated positive/ambiguous/negative correlation tests verify the stated decisions; no analyst evidence-completeness score is invented.

Sigma process predicates map fixed columns `Image`, `ParentImage`, `CommandLine` to normalized fields and execute only on Sysmon event 1 records. The project inserts event values with SQL parameters. It never executes commands from logs. Case labels and expected outcomes are outside this schema.

Limits: 64 MiB per evidence file, 1 MiB per record/manifest, 250,000 unique events; split larger exports. Untrusted XML entities/DOCTYPE, duplicate JSON keys, traversal paths, escaping symlinks and dangling report evidence links are rejected. This is a local batch pipeline, not a streaming SIEM.

W3C records retain file/line identity: identical second-resolution rows may be separate legitimate requests. Cross-file W3C deduplication is not attempted without a trustworthy request identity. Structured identical event exports coalesce and retain their source references.
