# Telemetry contract and limits

This preview has working collection code and Windows PowerShell syntax/read-only prerequisite checks. Its bundled replay evidence is handcrafted fixture data; native IIS/Sysmon scenario captures remain pending. The same parser/detection pipeline consumes both modes, with provenance preserved in each dataset manifest.

| Source | Collection and fields | What it establishes | Prerequisites and limits |
| --- | --- | --- | --- |
| IIS W3C | Owned site's actual `#Fields`, UTC date/time, client/server address, server port, method, URI stem, status/substatus/Win32 status, duration, protocol | A request and its HTTP outcome | No application tenant or request ID join is supplied by IIS automatically. One-second timestamps and buffering limit timing. Query strings, credentials, cookies, referrer and headers are not enabled. |
| Application JSONL | Server-generated request ID, authenticated actor/tenant/role, resource/policy context, job/action/outcome; launch parent PID/start and child PID/start interval | Policy violation or denial; an instrumented process launch | Never derive authenticated identity from request headers. No cookie/password logging. Log tampering remains possible within the app's writable data directory. |
| Sysmon event 1 | Original structured XML with ProcessGuid, ParentProcessGuid, image, command line, PID, parent PID, start time, User, hashes where supplied | Observed process creation and ancestry | Sysmon must be installed before the worker starts. AppPoolIdentity and in-process topology are checked separately. A child of `w3wp.exe` alone is not conclusive maliciousness. |
| Sysmon event 3 | ProcessGuid, image, destination/source network tuple and timestamp | Observed connection associated with a process | Explicitly enabled by this config; Sysmon's default does not enable it. Missing local-loopback network evidence is unavailable visibility until measured. Connection alone is not proof of bytes transferred. |
| Sysmon event 11 | ProcessGuid, image, TargetFilename and creation timestamp for the fixed data root | File creation/overwrite | Does not establish general file reads. Controlled receiver bytes plus hashes supply a separate transfer observation. |
| Sysmon event 5 | ProcessGuid, PID, termination time | Additional lifetime boundary | Retained in native XML for investigation even when a particular detector does not use it. |
| Windows PowerShell operational 4103/4104 | Original provider/channel/version/record ID and named EventData, including ScriptBlockId, MessageNumber/MessageTotal and ScriptBlockText when supplied | Selected script-processing evidence | Baseline invokes Windows PowerShell 5.1. Supplementary script-block policy enables 4104; module logging 4103 is not separately enabled. PowerShell 7's `PowerShellCore/Operational` is outside this baseline. Partial fragments must not be presented as a complete script. |
| Security 4688 | Original event version and fields, including hexadecimal NewProcessId/creator ProcessId and command line when supplied | Supplementary OS process evidence | Successful process-creation auditing and command-line policy are distinct prerequisites. This collector selects PID/time candidates with observed PID-reuse bounds; it does not elevate them to Sysmon GUID certainty. |
| Local receiver | Timestamp, actual bytes, SHA-256, peer and relative artefact file; original bytes preserved | The bounded local receiver obtained those bytes | Receiver startup is a separate harness step. Content matches support only the synthetic local transfer demonstrated, not real customer exfiltration. |

Application login failure is an application security event; it is not automatically Windows 4625. Scheduled tasks and Security 4698 are not part of this core implementation. An uploaded `.aspx` file is not assumed executable under ASP.NET Core, and this core does not claim a working web shell.

## Original records and collection boundaries

`Collect-Evidence.ps1` reads only the owned application's JSON file and IIS site's W3C directory. Sysmon queries use a bounded window plus a default 60-minute process ancestry lookback. Roots must have an observed `\inetsrv\w3wp.exe` image and the dedicated pool's `-ap IISPurpleLab` command line. Descendants are selected by `ParentProcessGuid`; file/network records are selected by those process GUIDs. The collector retains the selected root/descendant process-creation records even if they predate the request window. If it cannot observe a root, it records that limitation rather than exporting unrelated web processes or fabricating a parent.

Windows sources use an `<Events>` wrapper containing each actual `EventLogRecord.ToXml()` result. Provider, channel, event version, record identity, UTC event time, computer, execution metadata and named fields remain intact. No localised formatted messages are used. XML wrappers and whitespace are export packaging; no EVTX is invented. Application and IIS rows are unchanged selections with links to original file and line positions. The collection timestamp is separate from event timestamps.

Every source descriptor in `manifest.json` supplies `path`, `source`, `format`, SHA-256 and byte count. The manifest also includes hashes for metadata and stored receiver bytes, tool/configuration versions where observed, script hashes, collection conditions, channel availability and limitations. Manifest origin values distinguish native Windows, sanitised derivatives and handcrafted fixtures. The manifest itself cannot include its own hash; preserve an external manifest hash when transferring a bundle. `validation.json` is produced after collection and is not part of the collector's pre-existing hash inventory.

PowerShell fragments are retained intact in raw XML. The [normaliser](../analysis/iis_purple/normalize.py) groups host/provider/channel/process/ScriptBlockId records, checks numbered `1..MessageTotal` coverage and conflicting duplicate text, and annotates fragment completeness with evidence IDs. It does not silently concatenate partial or conflicting scripts. [Handcrafted parser tests](../tests/test_normalize.py) cover these decisions. The native gate verifies delivered events, not all possible engine versions; fragment behavior still needs an actual Windows capture test.

## Permissions, side effects, and analyst interpretation

Administrative setup changes IIS resources and installs Sysmon on the disposable VM. Supplementary logging modifies only two saved registry values and one audit subcategory, with conditional restoration. Collector reads require elevation for Security logs and process owners. The collector writes bundles and reads/hashes artefacts; those reads can themselves generate ordinary host telemetry. It does not collect database contents, password files, or all workstation logs. Logs/configuration remain private until deliberately sanitised.

Missing/inaccessible channels are `unavailable`; an accessible channel without selected events is `no_selected_events` or `no_project_chain_observed`. Neither means an attack failed. The installed preflight checks configuration and actual process identity. `Test-Capture.ps1` checks native event delivery and bundle integrity; application reproduction outcomes, detector correctness and remediation are separate gates.

The collector uses manual export. Pipeline runtime is offline processing time; this release has no measured continuous live detection cadence. Event counts and bundle sizes describe selected/exported evidence; they do not measure CPU overhead, VM-wide Sysmon storage, analyst savings, or production impact. Broad VM-side process/network collection has a real overhead that must be measured separately.
